# GAS版：Googleスライドでワンクリック照合（プロトタイプ）

納品がGoogleスライドである点を活かし、**ファイルの受け渡しをせず、スライド上でワンクリック**で
色番号の照合を行う Apps Script です。元ブリーフの「p5-6が指示、p7が貼り付けページ」という構造
（＝1つのCRシートに *指示テキスト* と *提出クリエイティブ画像* が同居）を前提にしています。

- 設計思想：[../docs/AIレビューの仕組み_設計書_チーム共有用.md](../docs/AIレビューの仕組み_設計書_チーム共有用.md)
- 照合ロジック：[../docs/照合ロジック仕様_たたき台.md](../docs/照合ロジック仕様_たたき台.md)
- CLI版（Python）での実証：[../poc/](../poc/)

## 何をするか

実物の7月CRシートの構造（1投稿＝複数スライド、投稿IDで識別、投稿日一覧/テンプレ/FIXが混在）に合わせ、
**同じ投稿ID（`IG_fe＿投稿no,N_◯月◯日…【タイトル】`）のスライド群をまとめて**照合します。

1. その投稿のスライド群の **指示テキスト**（文字データ）から、正解の色番号を取得
2. 同じ群の **提出クリエイティブ画像** を **Drive の OCR** で読み取り、色番号を抽出
3. 機械的に照合し、結果を **スライド上のコメント（テキストボックス）** と **スピーカーノート** に出力
   - ❌ 取り違え疑い（正解に無い色番号）／⚠ 未検出（正解にあるが読めず・未反映）／✅ 一致

投稿日一覧ページ（複数の投稿IDが並ぶ）・テンプレページは自動で対象外にします。

> AIに正誤を判断させず、OCRは「読む」だけ・一致判定は機械。これがこの仕組みの肝です。

## ★ まず「構造を診断」を実行

スライドの並び（どのページが指示・貼り付け・一覧か）は案件で変わり得ます。実行前に
**AIレビュー → 構造を診断** を1回押してください。各スライドの種別・投稿ID・テキスト数・画像数・
読めた色番号を一覧にした **Googleドキュメント** が生成されます。そのURLを共有いただければ、
実際の構造に合わせて対応づけを最終調整します（現状は投稿ID単位のグルーピング＋ID無しページは直前投稿に従属）。

## 導入手順

1. 対象のGoogleスライド（CRシート）を開く → 拡張機能 → **Apps Script**
2. `Code.gs` の内容を貼り付け
3. **HTMLファイルを追加**：エディタ左「ファイル ＋」→ **HTML** → 名前を **`Sidebar`**（拡張子なしで入力＝`Sidebar.html` になる）→ `gas/Sidebar.html` の内容を貼り付け
4. `appsscript.json` を表示（設定で「appsscript.json マニフェスト ファイルをエディタで表示」をON）し、本リポジトリの内容に置き換え
   - これで **Drive 詳細サービス（v2）** と必要な OAuth スコープが有効になります
5. 保存 → スライドを再読み込みすると、メニューに **「AIレビュー」** が出ます
6. **AIレビュー → ▶ レビューパネルを開く** でサイドバーが開きます（初回のみ権限承認）

## 使い方（サイドバー推奨）

**AIレビュー → ▶ レビューパネルを開く** で、右側にサイドバーが出ます。結果は色分けチップで表示されます：
**❌ 取り違え疑い**（提出物にあるが正解に無い）／**⚠ 未検出**（正解にあるが読めず・未反映）／**✅ 一致**。

- **選択したページを照合**：左サムネイルで選んだページ（複数可）をピンポイント照合
- **番号で照合**：入力欄に `7` ／ `5,7` ／ `9-11` を入れて照合
- **この投稿をまるごと照合**：選択中スライドが属する投稿の全ページを照合
- **全投稿を照合**：貼り付け画像のある全投稿を照合（時間がかかります）
- **構造を診断** / **結果コメントを消す** / **選択を更新**

> メニューからも同じ機能を実行できます（結果はダイアログ表示）。サイドバーの方が見やすいので通常はパネル推奨。

> ピンポイント照合（ページ選択・番号指定）では、**OCRは選んだページの画像だけ**を対象にしつつ、
> **正解の色番号はそのページが属する投稿の指示テキストから自動で引き**ます。貼り付けページ単体でも正しく比較できます。

## 設定（`CONFIG`）

| 項目 | 既定 | 説明 |
| :- | :- | :- |
| `ocrLanguage` | `ja` | Drive OCR の言語 |
| `writeComment` | `true` | スライド上にテキストボックスで結果を出す |
| `writeSpeakerNotes` | `true` | スピーカーノートに詳細を出す |
| `codePattern` | `[A-Z]{2}\d{3}[A-Z]?` | 色番号の書式 |

## プロトタイプの制約（実データで詰める前提）

- **スライド構造への依存**：いまは「投稿ID単位でグルーピングし、ID無しページは直前投稿に従属」で対応づけています。
  「構造を診断」の出力を見て、実際の並び（指示ページと貼り付けページの位置関係）に合わせ込みます。
- **OCR精度**：装飾フォントや写真上の細い白文字は読み落とし得ます（設計書でいう Phase 1 の重点）。
  Drive OCR で不足する場合は Cloud Vision API へ差し替え可能（精度は上がるが GCP 設定が必要）。
- **確信度**：CLI版(v1)にあるOCRの確信度フィルタは、GAS(Drive OCR)では取得しづらいため、
  当面は「複数画像での検出回数」で代替。誤読対策は運用データを見て強化します。
- **対象は色番号**：まずは事故の多い色番号に集中。色ライン名・素材名・必須文言の照合は次段階。

## 次段階

- 指示↔貼り付けの対応づけを実スライド構造に合わせて確定
- 色ライン名・素材名・必須文言（注釈・CTA）の照合を追加
- 「コメント（青字）」運用に合わせた出力体裁の調整
- スプレッドシート形式CRシート／Slackテキスト指示の正解ソース取り込み
