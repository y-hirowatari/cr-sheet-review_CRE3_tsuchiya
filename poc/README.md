# PoC (v0)：CRシート単体の整合チェック

提出物（クリエイティブ画像）がまだ無い段階でも検証できる、**CRシート単体でできる機械照合**の実証コードです。設計思想（AIに判断させず機械照合する）が実データで動くことを示すのが目的。

- 考え方：[../docs/AIレビューの仕組み_設計書_チーム共有用.md](../docs/AIレビューの仕組み_設計書_チーム共有用.md)
- 仕様：[../docs/照合ロジック仕様_たたき台.md](../docs/照合ロジック仕様_たたき台.md)

## できること

1. **色番号↔色ライン名の整合**（シート全体）
   同じ色番号が別のライン名で書かれていないか＝取り違え/誤記を検出。
2. **キャプション使用色 ⊆（文字入れ指示 ∪ 対象商材）**（投稿単位）
   キャプションにあるのにシートのどこにも無い色番号＝キャプション側の取り違えを検出。
3. **投稿インベントリ**：媒体（IG/X）・投稿ごとの抽出色番号数・対象商材カバレッジ。
4. `--demo-typo`：正解を1文字だけ書き換えた擬似ミスを混ぜ、機械照合が検出できることを実演。

いずれも **AIに正誤を判断させず、抽出した文字列を機械的に集合比較** しているだけ。だから「自信ありげな誤判定」が起きない、というのが設計の肝の実証です。

## 使い方

```bash
pip install -r requirements.txt
python3 cr_check.py <CRシート.pdf> [<CRシート.pdf> ...] [--demo-typo]
```

CRシートPDF（クライアント素材）は `.gitignore` によりリポジトリに含めません。手元のファイルパスを渡してください。

## 実行結果（6月・7月／IG・X）

`sample_output.txt` に全文。要点：

- **色番号 89 種すべてでライン名の矛盾なし**（【1】OK）
- **照合対象の全投稿で、キャプションの色番号はシート側に存在**（【2】OK）
  → 今回の2シートは、この2観点では「きれい」。誤検知ゼロで通過。
- **デモ**：`BK073D → BK074D` の1文字取り違えを正しく検出し、コピペ用の正しい表記まで提示。
  → ネイルホリックで過去多発した「色番号の取り違え」を、まさに機械照合で捕まえられることの実証。

> つまり「今あるシートは問題なし」＋「もし1文字間違えたら確実に捕まえる」を、同じ仕組みで両方示せています。

## 実装上わかった勘所（v1へ引き継ぐ）

- **対象商材欄は不完全なことが多い**（例：カバレッジ 5/15）。よって 指示⇔商材 の差分は「エラー」ではなく参考。照合は「指示 ∪ 商材」を正解側集合に使うのが安全。
- **色チャート/特集系の投稿は色番号が対象商材欄にしか無い**（例：シアーカラー一覧、ゼリー、世界の海）。指示欄だけを見ると取りこぼす。
- **X投稿はキャプションのみ（IG転載）**。照合対象の色番号がシート側に無いため、自動的にスキップ（IG側と突き合わせる案はv1で検討）。
- **表記ゆれは実在**（`＋`↔`+`、スペース有無、`・`↔`▶`）。正規化必須だが、色番号そのものの1文字差は絶対に吸収しない。

## v0でやらないこと（v1以降）

- **提出画像のOCR照合**：本命。実際の提出クリエイティブ画像が入手でき次第、OCR→正解照合を実装し、色番号OCRの精度（`BL920`↔`BL921` の1文字差を読めるか）を実測する。
- 見切れ・コントラスト・文字サイズ・必須要素の画像側チェック。
- 正解ソース（Gスライド原本／スプレッドシート／コメント青字／Slack指示）の直接取り込みと、FIX/修正版の自動判別。
- キャプションの per-ambassador（@ハンドル単位）照合による、より細かい取り違え検出。
