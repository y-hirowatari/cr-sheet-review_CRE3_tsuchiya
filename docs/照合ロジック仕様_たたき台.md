# 照合ロジック仕様（たたき台）｜ネイルホリック

※実装担当向け。実物のCRシート（6月・7月投稿分／IG・X）の構造をもとにした初版のたたき台です。閾値・データ形式は検証しながら確定します。
※考え方の共有は [AIレビューの仕組み（設計書・チーム共有用）](AIレビューの仕組み_設計書_チーム共有用.md)、クリエイター向けの使い方は [AIセルフチェックの使い方（クリエイター向け）](AIセルフチェックの使い方_クリエイター向け.md) を参照。

-----

## 1. 基本方針

- AIは**判断せず、文字を読むだけ**。正誤は機械が文字単位で照合して決める（自信ありげな誤判定を防ぐ）。
- 「正解」はCRシート（文字データ）。誤りが混じり得るのは提出物側のOCRのみ。
- v1は**検知と提示まで**。修正反映はクリエイターの手で行う。

-----

## 2. CRシートのデータモデル（実物準拠）

1投稿（＝`IG_fe＿投稿no,N_M月D日(曜) 17:00 【タイトル】` の単位）は、次の要素を持つ。

```
投稿(post)
├─ 投稿ID: 媒体 / no / 投稿日時 / タイトル      例: IG_fe no,1 6月2日(火)17:00 【店頭POP(海&涼しげネイル)】
├─ ステータス: FIX / OLD / 仮 / テンプレ
├─ ページ(枚)ごとの「文字入れ指示内容」
│    └─ 色エントリ[]: { 色番号, 色ライン名 }   例: {BL920, Lagoon color}
│    └─ 添付テキスト（Ambassador's Comment 等）※照合対象外（参考）
├─ 対象商材
│    └─ 色番号[]（＋商材画像/色玉/格納先の有無）
└─ 投稿キャプション【初稿】/【修正版】
     └─ 使用色[]（「使用色 ▶」に続く色番号を「・」区切りで列挙）
```

### 色エントリの語彙（実物で確認できたもの）

- **色番号の形**：`^[A-Z]{2}\d{3}[A-Z]?$` に概ね合致。例：`BL920` / `WT045R` / `PU076D` / `WT082V` / `YE022F` / `BE047R`。
- **色ライン名（number ↔ line）**：`フレッシュカラーズ` / `ラメフレークカラーズ` / `モードカラーズ` / `くすみカラーズ` / `つめ用ファンデ＋` / `アートネイル` / `Lagoon color` / `Flower layered color` / `Nostalgic color` / `Dark Fantasy Color` / `Soulful color` / `Aurora Glitter` / `Sheer pearl color` など。
- **アイテム（色番号を持たない素材）**：`ラメ トップコート 01 大粒ラメ` / `03 繊細ゴールド` / `04 繊細シルバー`（`Top coat`）など。これらは色番号ルールの対象外として名称で扱う。

## 3. パイプライン

```
1. 正解ソースの確定   … 対象投稿のFIX/修正版を特定（OLD・初稿・テンプレは除外）
2. CRシート抽出       … 文字入れ指示 / 対象商材 / キャプション（修正版）から色エントリを構造化（文字データなので正確）
3. 提出物OCR          … 画像から文字抽出（唯一の誤差源）
4. 正規化             … 全角/半角・空白・区切り文字をそろえる（両側に適用）
5. 照合               … (a)シート内部の相互整合 (b)提出物 vs 正解
6. レポート生成       … 指摘＋証拠＋正しい文言（コピペ用）
```

### 4. 正規化ルール（誤検知を防ぐ肝）

実物で表記ゆれが既に混在していたため、照合前に両側へ次を適用する。

| 対象 | 例（before → after） |
| :- | :- |
| 全角/半角記号 | `つめ用ファンデ＋` → `つめ用ファンデ+` |
| 空白の有無・種類 | `OR084Vフレッシュカラーズ` / `OR084V　フレッシュカラーズ` → `OR084V フレッシュカラーズ` |
| キャプションの区切り | `・` `▶` `,` を区切りとして統一 |
| ラベルゆれ | `使用色 ▶` / `使用色▶` → `使用色:` |
| 色番号の英字 | 大文字化（`bl920` → `BL920`） |

> 注意：正規化は「照合を通すため」のもの。**色番号そのものの1文字違い（`BL920`↔`BL921`）は正規化で吸収してはいけない**。ここを潰すと取り違えを見逃す。正規化対象は記号・空白・ラベルに限定する。

## 5. チェック項目と判定方法

| # | 項目 | 種別 | 判定方法 |
| :- | :- | :- | :- |
| 1 | 色番号・色名・素材名の一致 | 客観 | 正解の色エントリ集合と提出物OCRを集合照合。過不足・1文字違いを検出 |
| 2 | 番号↔ライン名の整合 | 客観 | 同一色番号に紐づくライン名が投稿内・シート内で矛盾しないか |
| 3 | シート内部の相互整合 | 客観 | 文字入れ指示 ⇔ 対象商材 ⇔ キャプション（修正版）の色番号集合の差分 |
| 4 | 文言の一致 | 客観 | キャプション（修正版）等の文字列を提出物OCRと照合。誤字脱字・抜け漏れ |
| 5 | 必須要素 | 客観 | CTA・ロゴ・注釈・価格・発売日等の有無 |
| 6 | 表紙の見切れ | 客観 | 1枚目の文字/ロゴがIGの安全領域外に出ていないか（座標判定） |
| 7 | コントラスト | 客観 | 文字色と背景色のコントラスト比が基準（暫定4.5）以上か |
| 8 | 文字サイズ | 客観 | 実機可読の最小サイズ（要基準確定）を下回っていないか |
| 9 | 配色 | 参考 | ブランドカラーからの逸脱の気づき提示のみ（トンマナ資料が無いためNG根拠にしない） |
| 10 | アート素材の出典 | 参考 | 絵画/アート素材が使われている投稿で、出典ルール確認を促す（正誤判定はしない） |

- 項目1〜8：**NG根拠になる客観チェック**。すべて証拠（該当ページ・該当文字列・数値）付き。
- 項目9〜10：**参考（気づき）**。NGにはしない。

## 6. 照合レポートの例（実物の1投稿を題材にしたフォーマット例）

対象：`IG_fe no,1 6月2日(火)17:00 【店頭POP(海&涼しげネイル)】` / ステータス FIX

正解（CRシート「文字入れ指示内容」より、@ssssssatoko 分）:

```
BL920 Lagoon color
BL921 Lagoon color
WT045R ラメフレークカラーズ
GD042R ラメフレークカラーズ
WT017A アートネイル
```

キャプション【修正版】の「使用色 ▶」: `BL920・BL921・WT045R・GD042R・WT017A`

レポート出力イメージ（※下の指摘は書式を示すためのサンプルであり、実データの断定ではありません）:

```
[OK]   色番号の相互整合（指示 ⇔ キャプション）: 5件一致
[NG]   提出物 vs 正解（色番号）
        - 提出物3枚目に "BL921" が見当たりません（正解: BL920/BL921/...）
          証拠: OCR結果に "BL92l"（末尾が数字1でなく英小文字l）を検出 → 要確認
        - 正しい表記(コピペ用): BL921 Lagoon color
[NG]   番号↔ライン名の整合
        - "WT045R" のライン名が提出物では "フレッシュカラーズ"、正解は "ラメフレークカラーズ"
[参考] 配色: 背景ブルーの彩度が過去傾向よりやや高め（トンマナ未定義のため参考）
```

このように、**「証拠」＝該当箇所・OCR結果・正しい文言**をセットで出すことで、リーダーは数秒で正誤を判断できる。

-----

## 7. v1スコープと非スコープ

**やる**
- 項目1〜5（文言・色番号/色名/素材名・相互整合・必須要素）の検知と証拠付き提示
- 正しい文言/色番号のコピペ用提示
- リーダー引き渡しバンドル（提出物＋AI結果＋直した点）

**やらない（v1）**
- 提出物の自動書き換え（レイアウト/編集データ保護のため）
- 配色・アート出典のNG判定（参考にとどめる）
- 正解ソース（Gスライド/スプシ、コメント青字/Slack指示）の完全自動吸収 ※段階的に対応

## 8. 未確定・要検証（実装前に詰める）

- 色番号OCRの読み取り精度：写真上の白文字・装飾フォント・細い色番号（`BL920`↔`BL921` の1文字差）— Phase 1の重点。
- コントラスト・文字サイズの基準値：リーダーから実例を集めて確定。
- 正解ソースの取り込み：スプレッドシート形式、スライドのコメント（青字）、Slack指示の反映フロー。
- キャプションの「初稿/修正版」自動判別と、FIX/OLD/仮/テンプレのステータス解釈。
